# “随材做”UI 参考原型

这里的 A、B、C 三套可运行页面是早期代码探索，只用于帮助理解可能的信息层级、交互范围和视觉方向。

它们不是正式候选设计，不能让负责人直接从 A、B、C 中选择，也不能作为实现 agent 的 UI 事实来源。流程验证者必须根据 [GitHub Issue #1](https://github.com/htk5257577/frontend-agent-lab/issues/1)，使用 AI 通过 Penpot 官方 MCP 重新生成 2–3 套有实质差异的 Penpot 原型，再由人选择。

## 查看参考原型

```bash
pnpm run prototype:ui
```

通过页面底部切换器或键盘方向键查看三个方向。URL 中的 `variant=A|B|C` 切换方案，`ingredients` 参数提供固定的已选食材状态。

## 正式设计任务

1. 阅读 Issue #1，区分已确认需求、待确认规则和范围外内容。
2. 运行这里的三个页面，只提取值得参考的问题和思路，不机械复制任何一套。
3. 在 Penpot 创建正式设计文件，连接官方 MCP，先验证 AI 能读取当前页面，再允许写入。
4. 让 AI 在 Penpot 中生成 2–3 套交互、布局或主题上有实质差异的候选方案。
5. 每套方案至少覆盖主路径、未选择食材、搜索无结果、菜谱无合适结果和菜谱详情，并包含批准的桌面与移动端视口。
6. 由人比较任务效率、信息层级、可理解性和视觉方向，只选择一套或明确组合规则。
7. 在 Issue #1 记录 Penpot 文件、页面/对象、批准版本、选择人和选择时间，并导出 `.penpot` 备份。
8. 从批准时刻起，Penpot 版本成为正式设计来源；本目录继续作为探索历史，不能与正式设计混用。

Penpot MCP URL 中包含的密钥属于秘密，不得写入仓库、Issue、截图或日志。当前仓库公开，只能使用示例数据和非敏感设计。
